# FUZIX on the embedded 80C188 (RCBus)

Deep-dive into the [`rcbus-80c188`](../kernel/platform/rcbus-80c188/) board — a
bare **80C188** (embedded 8086-class CPU) on the RC2014-style bus. It shares the
`i8086` CPU port and the `ia16-elf` GCC toolchain with the IBM PC, but it is a
very different machine: **no PC BIOS, no PC peripherals**, and — for now — no
segmented multi-process model. The shared CPU-level material (toolchain, the
segmented real-mode model, the context-switch contract) lives in
[8086.md](8086.md); this file is the 80C188-specific half.

> **Status (2026-08): the kernel builds to `fuzix.bin`.** After this tree's
> build-glue fixes (see §3) the `rcbus-80c188` kernel compiles and links with the
> real `ia16-elf-gcc`. It is not runtime-tested — there is no emulator wired up —
> and it deliberately runs the **swap-only** model until the segmented memory
> manager is brought over (see §2).

---

## 1. Toolchain

Identical to the IBM PC: the **ia16 GCC** cross toolchain (`ia16-elf-gcc` /
`ia16-elf-ld`, ELF 16-bit objects), selected by `cmake/toolchain-i8086.cmake`.
See [8086.md §1](8086.md#1-toolchain) for the full table. The board is built
with:

```
cmake -B build -DCMAKE_TOOLCHAIN_FILE=cmake/toolchain-i8086.cmake \
      -DFUZIX_CPU=i8086 -DFUZIX_PLATFORM=rcbus-80c188 \
      -DFUZIX_IA16_PREFIX=$PWD/toolchain/ia16-elf-gcc/bin
cmake --build build --target fuzix       # -> image/fuzix.bin
```

## 2. Memory model — swap-only, for now

Unlike the IBM PC (which uses the `bank8086` 4K-page segment manager), the
80C188 board currently runs the **swap-only** manager
([`mm/simple.c`](../kernel/mm/simple.c), `CONFIG_SWAP_ONLY`): a single process is
resident at a time and the rest swap to disk. Its `config.h` says as much — it
will *"need to set up a proper 8086 segmented model before this is useful"* — so
swap is a stopgap until the segmented model (shared with the PC, see
[8086.md §2](8086.md#2-memory-model)) is wired in here too.

Board memory parameters ([`config.h`](../kernel/platform/rcbus-80c188/config.h)):

| Setting            | Value        | Note |
|--------------------|--------------|------|
| `PROGBASE`/`PROGLOAD` | `0x0000`  | program starts at `cs:0` (vs `0x8000` on the PC) |
| `PROGTOP`          | `0xE000`     | |
| `PROC_SIZE`        | `128`        | a 64K segment (128 × 512) |
| `CONFIG_SPLIT_UDATA` | on         | udata is separate from the user image |
| `CONFIG_BANKS`     | `1`          | |
| `SWAP_SIZE`        | `130 + 2`    | +2 blocks for the udata; `SWAPDEV = 1`, `MAX_SWAPS = PTABSIZE` |
| `TICKSPERSEC`      | `50`         | |

The context switch is the platform's own
[`tricks.S`](../kernel/platform/rcbus-80c188/tricks.S) (the swap-only variant,
distinct from the banked ibmpc one described in [8086.md §2](8086.md#2-memory-model));
it compiles as part of the building kernel.

## 3. How this is wired into `fuzix-new`

The board links directly to an ELF image via a linker script
([`fuzix.ld`](../kernel/platform/rcbus-80c188/fuzix.ld), `LINK_STYLE=ld-elf`) with
no boot/disk-image packaging (`DISKIMAGE_STYLE=none`) — the source order lives in
[`cmake/platform-rcbus-80c188.cmake`](../cmake/platform-rcbus-80c188.cmake).

Two build-glue fixes were needed to make it compile and link with the real
toolchain:

- **Dropped `STARTUP(crt0.o)`** from `fuzix.ld`. `STARTUP()` makes `ia16-elf-ld`
  look for a file literally named `crt0.o` on its search path, but this CMake
  build passes every object explicitly with `crt0.o` first — so it failed with
  `cannot find crt0.o`. crt0's `.text` is already first because it is the first
  argument. (Same fix as ibmpc / pdp11.)
- **Added `fuzix_compile(${MEMALLOC_SOURCE})`** (`mm/memalloc_none.c`): the
  fragment compiled `${MM_SOURCE}` but not the allocator, so `kdata.o` had
  undefined `_memalloc`/`_memfree` at link.

## 4. Device drivers

No PC BIOS — the board talks to hardware directly:

| Area       | Files | Notes |
|------------|-------|-------|
| Disk       | [`devide.c`](../kernel/dev/devide.c), `devide_discard.c`, [`blkdev.c`](../kernel/dev/blkdev.c), [`mbr.c`](../kernel/dev/mbr.c) | `CONFIG_IDE`, `MAX_BLKDEV 2`, MBR partitions |
| Serial/tty | [`devtty.c`](../kernel/platform/rcbus-80c188/devtty.c) | serial console (`NUM_DEV_TTY 1`, `BOOT_TTY` = first serial) |
| Low level  | [`80c188.S`](../kernel/platform/rcbus-80c188/80c188.S) | board glue |

`NBUFS 5`, `NMOUNTS 4`.

## 5. Roadmap

The 80C188 is a bare embedded x86 on the RC2014 bus. For now it runs one process
via swap; the next step is to bring over the segmented `bank8086` model so it can
keep multiple processes resident like the IBM PC.

See [8086.md](8086.md) for the shared 8086 CPU/segmented model,
[ARCHITECTURE.md](../ARCHITECTURE.md) for where i8086 sits among all CPUs, and
[fcc8bit.md](fcc8bit.md) for the contrasting 8080/Z80 banked approach.
